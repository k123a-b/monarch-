# Card Monarchs

A multiplayer browser card game where Italian brainrot meets a satirical royal court. Every price, wager, balance, and payout is fictional virtual GBP, represented by integer pence. There are no payment, deposit, withdrawal, or redemption features.

The vanilla JavaScript SPA includes five pack tiers, an animated card reveal with optional synthesized audio, an inventory with vault and bulk sales, weighted ten-minute global pots, five-minute matched-stake friend tables, reserved two-party trades, active-play rewards, five leaderboards, and an accounting ledger.

## Technology

Vite bundles the HTML, CSS, and framework-free JavaScript frontend. A Vercel Function (`api/index.ts`) provides the JSON API and Google sign-in. Supabase provides managed PostgreSQL, accessed with Drizzle and the `pg` driver; transactional game operations use explicit transactions, per-account and per-round locking on pooled connections, and recent pulls use Drizzle ORM. Independent players can mutate their accounts concurrently while shared pot rounds remain serialized. Auth.js (`@auth/core`) handles Google OAuth and issues a signed, HTTP-only session cookie. Vercel Image Optimization serves generated pack/meme artwork and externally sourced leader portraits.

## Local development

Use Node.js 22 or later. Install dependencies with `npm install`, copy `.env.example` to `.env.local` and fill it in, apply the schema with `npm run migrate`, then run `npx vercel dev` (it runs Vite and the API together). See "Deploying to Vercel" below for the hosted setup.

`npm test` runs deterministic pack and game-rule checks. Optional deployment API checks run when `CARD_MONARCHS_TEST_URL` names a running deployment. Database integration checks require `CARD_MONARCHS_DATABASE_TESTS=1` and a `DATABASE_URL`. These create temporary test accounts, exercise the actual API handler and database transactions, and clean up afterward. Do not use production for database tests.

The Vercel and Supabase migration has not been deployed or run against a live database from the environment it was written in; verify sign-in, a pack purchase and image loading on a preview deployment first.

## Accounts and Google login

Sign-in is Google only; email/password accounts were removed with Netlify Identity. Each Google login must have a verified email. The Google subject remains the primary account key, and a unique verified-email link lets the same Google account recover its existing game account if its Auth.js subject changes. A new account is suggested a unique username based on the Google profile name, then must save a public username in the first-sign-in prompt. Open **Settings** to change the name, switch Google accounts, or log out. A new account receives a single £5.00 welcome credit when its game account is first provisioned. No age field is collected. Accounts created under Netlify Identity are not carried over: ids differ, so players start fresh.

Create a Google OAuth client (Google Cloud Console, APIs & Services, Credentials, OAuth client ID, Web application). Add `https://YOUR-DOMAIN/api/auth/callback/google` as an authorized redirect URI (plus `http://localhost:3000/api/auth/callback/google` for `vercel dev`) and set `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` and `AUTH_SECRET` (generate one with `openssl rand -base64 32`). The sign-in button is disabled until all three are set. Sessions last 30 days and are verified server-side on every request; the browser never supplies identity. New accounts must save a unique public username in a first-sign-in prompt before using the app; existing accounts retain their current usernames.

Before deploying the first-sign-in username prompt, apply `db/migrations/20261025190000_require_new_account_username.sql` with `npm run migrate`. It marks existing accounts as already named and requires new accounts to choose a public username.

Before deploying the free starter card and stepped play rewards, apply `db/migrations/20261025203000_progressive_rewards_and_starter_pack.sql` with `npm run migrate`. Each existing account receives one starter claim when this migration is applied.

Before deploying the daily Rewards wheel and card loadouts, apply `db/migrations/20261026095000_daily_spin_and_loadout.sql` with `npm run migrate`. It adds per-account spin-day/result state and a three-card loadout.

Before deploying Google account email linking, apply `db/migrations/20261026103000_link_google_email_to_account.sql` with `npm run migrate`. The migration adds a unique, case-insensitive Google email link; it does not merge or delete pre-existing duplicate accounts.

Before deploying the fourth loadout slot, apply `db/migrations/20261026110000_fourth_loadout_slot.sql` with `npm run migrate`. Existing accounts keep three slots; the fourth can be unlocked once for £350 in virtual cash.

## Economy and fairness

The four original packs use the base per-card odds, expressed as integers out of 100,000,000. Alpha/Mystery Gold is isolated from regular pools and numbered using a database sequence. Apex guarantees at least a Crown by replacing its lowest card if necessary. Chase rolls are per pack; they replace only an eligible lower-value, non-Alpha card. Normal template duplicates are avoided until a rarity pool is exhausted. Pack value may be above or below the purchase price; card values enter the balance only when cards are sold.

Every tenth successful purchase per account, across all pack types, now guarantees an Epic or better. The server reads the existing persisted `accounts.packs` counter under the purchase transaction lock; failed purchases do not advance it, and natural rare pulls do not reset it. If the milestone pack has no Epic or better, its lowest card is replaced by an independently selected Epic from that pack’s collection before the unchanged chase roll. Apex keeps its stronger Crown guarantee. Existing players keep progress from their lifetime pack count. Card sell values remain varied, fixed in integer pence and visible before selling; rarity guarantees do not promise profit.

The £10 World Leaders Pack has four cards. Its per-card odds are 74.92% Common, 19.2% Uncommon, 5.56% Epic, 0.31984% Crown, and 0.00016% Alpha; Common loses 1.08 percentage points to raise Epic by the same amount. Kim Jong Un is exclusive to the separate 1-in-45,000 pack chase roll, worth £210,000 virtual GBP. His reveal triggers a screen shake; reduced-motion preferences suppress the shake. Andy Burnham is an Epic with a slow center-screen portrait flight, and the Israel flag has its own blue-and-white star reveal.

Global pot winner probability is proportional to stake with no house rake. As soon as exactly one human enters a round, the system Pot Bot matches that player's total contribution from its unlimited virtual balance: the total prize pool is twice the human stake, and the human receives 2× their stake if they win. The bot automatically sits out and its matching stake is removed as soon as another human enters. The bot participates in the same weighted draw and may win, so the human is not guaranteed a payout. Friend tables escrow equal stakes and pay exactly twice the stake to the winner after five minutes. Unjoined tables refund their host. Requests settle overdue games before relevant game actions; a scheduled function also settles and creates rounds every minute. Settlement is idempotent, transaction-locked, and reflected in each player's ledger. Anonymous pot views show live server data; bot entries are created only for the matching condition above.

Active play sends visible-tab heartbeats every 30 seconds, only treating a tab with recent interaction as active. The server credits at most 45 seconds per heartbeat. Every 10 active minutes, the reward increases by 25 pence from 50 pence to £1.50, capped at £5.00 per UTC day; payouts are recorded in the ledger. Every account, including accounts created before the feature, can open one free starter pack in Rewards for one card from the Brainrot, Royalty, or World Leaders collection. Its rarity odds are 85% Common, 12% Uncommon, 2.5% Epic, and 0.5% Crown; it cannot award Alpha or chase cards and does not count as a paid pack milestone. The server allows one claim per account and records it when the card is granted. Browser visibility is an anti-idle signal, not a tamper-proof bot-detection system.

Rewards also includes one server-recorded daily spin per account and UTC day: three separate 25% no-prize slices, 10% for 25p, 7% for 50p, 5% for £1, 2.9% for £5, and 0.1% for £45. Positive prizes are credited to the virtual balance and ledger in the same transaction that marks the spin complete.

Every card has a fixed whole-pence sell value; power-ups depend on rarity. Most Common cards have no power-up; about one in five Common cards has a small Epic-odds adjustment or a 10p discount on every third successful pack opening. Uncommon adjusts Epic odds by ±0.15 points, Epic by ±0.75, Crown by ±1.5, Chase by ±3, and Alpha by ±4. Positive and negative effects are both possible. Pack reveals show the total card sell value against the actual pack price, so a pull can be worth less or more than the pack; card values enter the balance only when cards are sold. Players can equip up to three available cards in **Loadout**, then unlock a fourth slot once for £350 virtual cash. Their combined Epic-odds adjustment is capped at ±4 percentage points and shifts probability from Common/Uncommon into Epic when available. Equipping Kim Jong Un guarantees every second card in a pack is Uncommon or better. Equipped cards cannot be sold, vaulted, or offered in trades until unequipped.

Run `node scripts/balance-audit.mjs` for a reproducible 500,000-pack simulation including tenth-pack guarantees, median sell values, and rates for losses, small wins, 2× wins, and 10× jackpots. Each pack is regression-tested to allow all four outcomes. The audit does not connect to the database or change live randomness. Results describe virtual inventory values, not automatic cash credits or guaranteed returns.

All economy mutations serialize with a PostgreSQL advisory transaction lock. Pack cards are inserted in one statement to shorten the write lock. Leaderboard reads use a separate read-only snapshot without acquiring the game write lock. Transactions bound lock waits to five seconds and individual statements to fifteen seconds; busy requests roll back and return a retryable error without automatic replay of purchases. Browser refreshes do not overlap, stale view responses are ignored, and forms reject duplicate submissions while a request is pending. This locking policy prioritizes correctness for an initial game population. Higher traffic should replace it with carefully ordered account, trade, and round locks. Mutations check the request origin, verify the Identity session, validate inputs, and scope cards/trades to their owners. Database constraints provide additional protection against negative balances, duplicate friendships, and invalid reservations.

## Catalogue and artwork

The original named roster contains 60 brainrot templates, 28 court templates, four chase cards, and Mystery Gold: 93 total. The brief's brainrot subtotal of 58 did not match its 60 explicitly listed names; all named cards were retained. Chase is a sixth visual tier alongside the five normal rarities.

The world expansion contains both leadership roles from 195 countries, including the collective Swiss Federal Council, plus 40 standalone national flag cards. The Leaders view can filter flag cards separately. Leader rarity and fictional GBP values use 2024 World Bank GDP as a country-power baseline, with recognition overrides for widely known figures; the featured Donald Trump (£230 Epic) and King Charles III (£75 Epic) values are fixed. These are illustrative game ratings, not objective or real-world valuations. Israel's flag remains an Epic worth £50. Shared leadership roles are represented by one card; the same person serving different countries has a separate country card. The roster is a dated snapshot, not a promise of real-time political accuracy. `shared/leaders.json` retains the reference, retrieval date, individual article links, and portrait URLs. Leader portraits are sourced from individual Wikipedia articles; image licenses and authorship are available through those sources. The 40 flag cards use bundled PNG artwork from FlagCDN, with the ISO country-code filename and source listed in each card. `shared/country-gdp.json` records the World Bank source and 2024 snapshot; refresh it with `npm run sync:country-gdp` before rerating a future catalogue. Three leader source pages had no available portrait and use a bundled neutral silhouette placeholder, labeled as unavailable in assistive text.

Pack and meme art was generated for this project; it is illustrative rather than canonical meme photography. `scripts/art.mjs` and `scripts/portraits.mjs` regenerate artwork through the Netlify AI Gateway (`NETLIFY_AI_GATEWAY_KEY` / `NETLIFY_AI_GATEWAY_URL`), a development-time tool that is not used by the deployed site without storing credentials. `scripts/flags.mjs` downloads and bundles all flag-card PNGs from FlagCDN. `scripts/leaders.mjs` refreshes the roster from a downloaded reference page at `/tmp/leaders.html`; review the results before publishing roster changes. Stable country/name hashes preserve template IDs. Retain retired templates while players still own them.

## Deploying to Vercel

1. **Supabase.** Create a project. Under Connect, copy the _Transaction pooler_ connection string (port 6543) and use it as `DATABASE_URL`. Do not append `?sslmode=`. Run `DATABASE_URL=... npm run migrate` once, and again after any new file appears in `db/migrations/`. The last migration turns on row level security so Supabase's public Data API cannot read or write game tables; the server connects as the database owner, which bypasses it.
2. **Google.** Create the OAuth client described above.
3. **Vercel.** Import the repository (root directory: the folder holding `package.json`; framework preset Vite). Add environment variables: `DATABASE_URL`, `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`. Redeploy after the first set, then add your final domain to the Google redirect URIs.
4. **Settlement.** Overdue pots and tables are also settled whenever someone loads the pot or acts, but a scheduled sweep keeps them settled when nobody is online. `GET /api/cron/settle` runs it and requires `Authorization: Bearer $CRON_SECRET`. Per-minute schedules need a Vercel Pro plan; to enable one, set `CRON_SECRET` and add `"crons": [{"path": "/api/cron/settle", "schedule": "* * * * *"}]` to `vercel.json`. On the Hobby plan crons may run at most daily, and a per-minute entry makes the deployment fail, so none is configured by default.
